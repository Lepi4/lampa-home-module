# Lift: дополнительный источник в карточке

Реализован 12.11.2026. Модуль `2026.11.12.4`, Android MC `1.16.42` / `1160`.

Кнопка **Lift** появляется в карточках TMDB фильмов, сериалов и аниме. Она использует существующие профиль, родительские ограничения, очередь прогресса и раздел «Продолжить».

## Первый запуск

1. Администратор включает `Lift VP9` в настройках нужного профиля. Глобальный флаг БД `module_lift` должен равняться `1`.
2. В карточке выбирает Lift, находит видео, сверяет название и год.
3. Для сериала отдельно выбирает серию Lift и соответствующие сезон/серию TMDB. Нумерации могут различаться; позиция сохраняется по TMDB.
4. Подтверждает соответствие, выбирает озвучку и запускает видео.

Подтверждённая привязка общая для пользователей сервера. Создавать и изменять её может только администратор взрослого профиля. Детский профиль получает только подтверждённый вариант, только при включённом источнике и после проверки ограничений карточки.

Для уже подтверждённого фильма доступен пункт «Найти другой вариант». Для сериала — «Добавить серию / другой вариант». Самостоятельный поиск по названию не считается доказательством соответствия: автоматической привязки первого результата нет.

## Формат и качество

Принимается только `streams.dash_vp9`: DASH/WebM VP9, явный MIME `application/dash+xml`. Переключения на AV1 или HLS нет. Встроенный Media3-плеер использует аппаратный VP9-декодер; отсутствие подходящего декодера завершает запуск с объяснением.

Варианты качества берутся из MPD, а не из маркетингового поля FHD. Учитывается общий предел видео конкретного устройства (`devices.cfg.maxh`); фильтр торрентов (`playback.max_height`) его не подменяет. Плеер дополнительно применяет локальный предел, проверяет ID, codec/profile, размеры и поддержку декодером до начала воспроизведения; меню качества оставляет только разрешённые варианты. Озвучка выбирается по проверенному `Representation@id`, сопоставленному с `audio.order`; язык и индекс массива не заменяют это соответствие.

## Позиция и повторный запуск

Ключи остаются `movie-<tmdb>` и `tv-<tmdb>-s<season>e<episode>`. Транспортный hash использует существующую строку канонического прогресса либо стабильный числовой ключ. Смена источника не создаёт отдельную историю просмотра.

Перед запуском общий обработчик дожидается доставки очередей прогресса и читает серверную позицию. Если позиция ненулевая, пользователь выбирает продолжение или начало. Для другой версии видео это прямо обозначается в диалоге. После диалога сервер заново получает поток, а общий обработчик повторно проверяет актуальную позицию и серверные часы. Сохранённая запись «Продолжить» содержит ID, редакцию, привязку и имя озвучки; временный CDN URL в неё не записывается.

Смена профиля, уход со страницы, отмена или новый запуск инвалидируют старые callbacks. Нативный запуск повторно проверяет доступ и ревизию привязки.

## Настройка сервера

Значения доступа провайдера передаются окружением процесса Lampac, не через APK и не через браузер:

```ini
# /etc/lampac/lift.env, root:root, 0600
LIFT_API_BASIC_B64=<base64 user:password, supplied locally>
LIFT_CDN_HOSTS=<comma-separated verified CDN hostnames>
# Optional:
LIFT_API_ROOTS=https://api.faphz.com/,https://api.twemd.ws/
LIFT_USER_AGENT=<provider-compatible Android TV user agent>
```

```ini
# /etc/systemd/system/lampac.service.d/lift.conf
[Service]
EnvironmentFile=/etc/lampac/lift.env
```

После настройки окружения нужны `systemctl daemon-reload` и перезапуск Lampac. В `init.conf` → `plugins.items` добавляется:

```json
{"url":"{localhost}/lift.js","status":1,"name":"Lift VP9","author":"home"}
```

API Basic передаётся только API провайдера. CDN получает User-Agent, без Home session и API credentials. MPD и вложенные адреса проверяются по HTTPS и точному списку разрешённых CDN. Редиректы, DRM, динамический/многопериодный MPD и внешние XML-ссылки не принимаются. Новые хосты CDN необходимо сначала проверить и добавить в серверное окружение.

В `manifest.json.tree` включаются только четыре C#-файла Lift. JS доставляется как обычные файлы модуля и объединяется обработчиком `/lift.js`; добавлять JS в tree нельзя.

## API

Все `/home/lift/*` требуют Home session; ответы не кешируются. Администраторские операции: `POST find`, `catalog`, `episodes`, `bind`. Операции просмотра: `GET item`, `POST options`, `resolve`, `position-context`. `resolve` требует `voice_name` и `binding_revision`.

`bind` принимает независимые `season/episode` TMDB и `provider_season/provider_episode` Lift. Сервер проверяет существование эпизода TMDB, однозначность эпизода Lift, доступность VP9/MPD и сопоставление озвучек до сохранения.

## Проверки и ограничения

Проверены компиляция всего HomeMedia, 28 регрессий прогресса, 28 selftest TlV2, 17 проверок Lift core, 45 JS-проверок запуска/отмены/перенумерации и существующего воспроизведения, сборка подписанного APK и 26 Android unit-тестов. На двух серверах прошла цепочка поиска, подтверждения фильма, options/resolve, авторизации и получения реального MPD и фрагментов HTTP 206; `ffprobe` подтвердил VP9 1920×1080. Некорректная ревизия и запрос без сессии отклоняются.

Рабочий пример — The Odyssey (2026): MPD VP9 486/720/1080, четыре озвучки. Это не гарантирует 1080p или доступность VP9 у всего каталога.

Серии запускаются по одной, через выбор подтверждённой серии. Автоматического перехода на следующую серию Lift пока нет. Интерфейс не создаёт отдельный каталог Lift, не включает его в автоматический выбор источника и не добавляет VK в карточки. APK до 1160 сообщает о необходимости обновления. Проверка физических кадров и звука на телевизоре остаётся отдельной приёмкой: ADB тестового устройства во время выпуска был недоступен.
