# ТВ на Dune: адрес потока 127.0.0.1 — 03.11.2026

Сеть «Коробка»: Lampac/HomeMedia `192.168.1.197`, Dune Magic 4K Plus
`192.168.1.101`. Наблюдалось ожидание воспроизведения при заполненном буфере.

## Причина на сервере

HomeMedia обращается к своему Channel Manager по `http://127.0.0.1:3002`.
Channel Manager формирует абсолютные ссылки M3U на основании Host запроса.
HomeMedia сохранял их в общем кэше и отдавал приставкам без преобразования.
Рабочий `/tv/channels` вернул 245 каналов с адресом `127.0.0.1:3002`.
Для Dune это адрес самой приставки, поэтому полный буфер на сервере не доказывал
доставку потока плееру. В момент диагностики Channel Manager держал «Первый канал»
с буфером 12 секунд и скоростью около 7,5 Мбит/с; его единственный клиент был
127.0.0.1, то есть серверный прогрев. У Dune были соединения с Lampac:9118,
прямого клиента Dune у Channel Manager не было.

## Исправление HomeMedia 2026.11.03.2

При формировании `/tv/channels` loopback-host заменяется именем сервера из
`Request.Host.Host`. Порт, схема, путь и query сохраняются. Внутренний кэш и URL
прогрева остаются локальными. Существующие внешние и LAN-адреса не изменяются.
Фиксированный IP в код не добавлен; каждый клиент получает адрес относительно
того сервера, к которому обратился. Панельные ссылки не менялись.

Код: `TvStore.ClientStreamUrl` в `TvGuide.cs`. Выполнены семь C#-проверок:
IPv4, hostname, IPv6, query, сохранение внешнего URL и относительных путей.
Сценарий: `server-mod/tests/tv-stream-url.test.py`.

## Доступ к Dune

ADB-подключение запрошено через SSH-forward шлюза «Коробки». Dune отвечает
на HTTP, но `192.168.1.101:5555` отвергает TCP-соединение. Без включения сетевой
отладки запрос RSA-разрешения на экране не возникает. APK не устанавливался,
приложение и воспроизведение удалённо не запускались. Логи декодера через ADB
пока недоступны; исправление серверной ссылки само по себе не подтверждает
изображение на экране Dune. Временный ADB-forward закрыт.
